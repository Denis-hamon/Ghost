Measure,  abstain,  reinforce — repeat.

One four-step contract closes the loop: every grounded outcome you report grows the pool and widens the regime where GHOST can answer.

Preflight — free checks

Does the diff apply? Compile? Near-full rewrite? Deterministic, zero tokens — run before anything else.

Risk scan — the ghost scores

State + diff embedded with UniXcoder-base, compared to every past outcome: nearest failure versus nearest success.

Run — then report grounded

Run your tests, send back the measured outcome with its method. It pairs by call_id for the flywheel.

Questions & Answers

What is GHOST?

A world model of patch outcomes for coding agents. It embeds (buggy state + draft diff) into the space where 207 labeled past runs live, and scores the draft by its distance to failures versus successes. Served over MCP; advisory only.

Does it generate or rewrite patches?

No. GHOST never generates code — it measures. Generation stays with your agent, which is exactly why the measurement complements it instead of competing with it.

Why does it answer “abstain” so often?

The verdict guarantee (acc ≥ 0.95) only holds on ~10% of the query space today. Outside it, any answer would be a guess. Abstention names the nearest pool family and its coverage — the flywheel exists to close that gap.

Can it block my agent’s actions?

Not this service. GHOST is advisory by construction. Blocking lives in separate measurement-governed machinery (FR-21) requiring certified precision strictly above an economic bar — a regime no instrument has crossed yet.

What counts as a grounded outcome?

An outcome measured by execution — a test-suite verdict, a CI result, a human-verified run. Outcomes without a measurement method are rejected from reinforcement.

Is there an LLM inside?

Not in the decision path. Fixed encoder, geometric scoring, execution-grounded labels. A judge-ensemble variant was measured and deliberately parked (owner decision, 2026-08).
