The ghost of every past run grades your patch draft.

GHOST is a goal-free world model for coding agents, served as an MCP server. It compares your candidate diff to the geometry of past run outcomes — failures to avoid, successes to imitate — before you spend the execution. And when it does not know, it says so.

01what it is

Know the risk before you run.

Coding agents spend executions on drafts that fail. GHOST reads the draft first and answers one question — does this look like the patches that worked before? — with no goal statement, no judge, and no pretending beyond its measured regime.

goal-free

No task description needed

The score is the distance to the nearest past failure minus the distance to the nearest past success, in latent patch space — a failure attractor that works without acceptance criteria.

calibrated

Abstention is the product

Verdicts are served only inside a regime measured by cross-validation (accuracy ≥ 0.95). Everywhere else the response is abstain, with the reason and the nearest pool family named.

grounded

Only real outcomes count

Reinforcement accepts execution-grounded results (pytest-f2p, ci, human…). A model’s opinion about its own patch is rejected — always.

02how it works

Measure, abstain, reinforce — repeat.

One four-step contract closes the loop: every grounded outcome you report grows the pool and widens the regime where GHOST can answer.

Preflight — free checks

Does the diff apply? Does it compile? Near-full rewrite? Deterministic, zero tokens, run before anything else.

preflight_patch(repo_path, diff_text)
# → { ok, checks: { apply, compile } }

Risk scan — the ghost scores

State + diff are embedded (UniXcoder-base), composed, and compared to every past outcome: nearest failure vs nearest success.

risk_scan(state, diff, reporter)
# → low_risk | high_risk | abstain
#   + call_id + family diagnosis

Run — then report grounded

Run your tests, then send the measured outcome back with its method. It pairs with the scan by call_id for the flywheel.

report_outcome(call_id, passed,
  grounded_by="pytest-f2p")

04install

Works with your agent stack.

GHOST speaks MCP — any client with an MCP server list can use it. Remote HTTP transport keeps the weights and the pool on the serving host; one URL is all the client needs.

Remote HTTP (recommended)

# Claude Code
claude mcp add --transport http \
  ghost http://<host>:8093/mcp

# opencode / Cursor / any mcpServers client
{ "mcpServers": { "ghost": {
    "url": "http://<host>:8093/mcp" } } }

Local stdio (colocated)

{ "mcpServers": { "ghost": {
    "command": ".venv/bin/python",
    "args": ["server/ghost_server.py"]
} } }
# pool + calibration served from data/ ·
# env: LI_POOL_JSON, LI_RISK_CALIB…

With GHOST_TOKEN set, the server requires Authorization: Bearer … and refuses to boot if the token cannot be enforced (fail-closed). Without it: internal network only.

05open

Open instrument. Open measurements.

The calibration constants are served alongside the pool — clients can audit the regime before trusting a single verdict. The server code is Apache-2.0, born inside an open measurement project where every number on this page was produced, challenged, and logged.

audit

Served calibration

τ and the LOAO regime are pinned in governance artifacts shipped with the server — not folklore.

provenance

Sealed pools

Each pool version carries content-hash provenance (lineage, author strata, sha256). A promotion swaps, discloses, and can roll back.

no judge

Non-LLM by design

The decision path contains zero LLM judges — GHOST exists to complement the models that call it, not imitate them.

07why

Why use GHOST?

It saves executions

A preflight pass is free; a risk scan is one embedding. Both happen before the expensive part — running the draft against the world.

It cannot flatter you

No confidence scores, no vibes. A verdict is a geometric distance to past failures and successes, served only where the geometry has been proven.

It tells you when it’s blind

Out of regime → abstain + the nearest family and its coverage. Your agent decides with its own tests, and the outcome strengthens the model.

It compounds

Grounded outcomes feed a nightly flywheel: deduplicated, stratified by author, poison-flagged, promoted to new pool versions under disclosure.

08questions & answers

Questions & answers

What is GHOST?

A world model of patch outcomes for coding agents. It embeds (buggy state + draft diff) into the same space where 207 labeled past runs live, and scores the draft by its distance to failures versus successes. Served over MCP; advisory only.

Does it generate or rewrite patches?

No. GHOST never generates code. It measures. Generation stays with your agent — that is exactly why the measurement complements it instead of competing with it.

Why does it answer “abstain” so often?

Because the verdict guarantee (acc ≥ 0.95) only holds on ~10% of the query space today. Outside it, any answer would be a guess. Abstention names the nearest pool family and its coverage, so you know what data is missing — and the flywheel exists to close that gap.

Can it block my agent’s actions?

Not this service. GHOST is advisory by construction. Blocking authorization lives in a separate, measurement-governed machinery (FR-21 in the parent project) that requires certified precision strictly above an economic bar — a regime no instrument has crossed yet.

What counts as a grounded outcome?

An outcome measured by execution — a test-suite verdict (pytest-f2p), a CI result, a human-verified run. Outcomes reported without a measurement method are rejected from reinforcement. Self-declared successes do not enter the pool.

Is there an LLM inside?

Not in the decision path. Embeddings are a fixed encoder (UniXcoder-base); scoring is geometry; labels come from executed tests. An ensemble with an LLM judge was measured and deliberately parked — the instrument’s value is being a non-LLM complement to LLMs.
