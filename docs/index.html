The ghost of every past run grades your patch draft.

GHOST is a goal-free world model for coding agents, served as an MCP server. It compares your candidate diff to the geometry of past run outcomes — failures to avoid, successes to imitate — and predicts before you spend an execution. And when it does not know, it says so: calibrated abstention is the product.

What it is

An advisory oracle for patch-consequence prediction

Coding agents spend executions on drafts that fail. GHOST reads the draft before the run and answers one question: does this look like the patches that worked before? — without needing a goal statement, without a judge, and without pretending to know beyond its measured regime.

👻

Goal-free by construction

No task description, no acceptance criteria required. The score is the distance to the nearest past failure minus the distance to the nearest past success — a failure-attractor in latent patch space.

🤫

Abstention is the product

GHOST only answers inside a calibrated regime (measured accuracy ≥ 0.95). Outside it, the response is abstain with the reason — the ghost stays silent when it does not know.

🛡️

Advisory only, grounded always

Nothing blocks, nothing replaces your tests. Reinforcement accepts only execution-grounded outcomes (a measured method, never the model's opinion).

How it works

Four steps, one feedback loop

Preflight — free deterministic checks

Before spending a model call: does the diff even apply? Does it compile? Is it a near-full rewrite? Zero tokens, immediate signal.

# deterministic, zero-LLM
preflight_patch(repo_path="/path/to/repo", diff_text="diff --git …")
# → { ok: true, checks: { apply, compile } }

Risk scan — the ghost scores the draft

The state text and the diff are embedded (UniXcoder-base, 768-d), composed, and compared to every past outcome in the pool: distance to nearest failure minus distance to nearest success. The verdict is served only inside the measured regime.

risk_scan(state_text="buggy module…", diff_text="…",
          reporter="your-agent-id")
# → { decision: "low_risk" | "high_risk" | "abstain",
#     attractor_score, confidence, call_id,
#     family: nearest pool family + coverage }   (v0.4.0)

Run the real tests

GHOST never substitutes execution. The draft is applied, the suite runs, the outcome is observed — that observation is the only label the system trusts.

Report the grounded outcome — close the loop

The measured pass/fail goes back with its method (pytest-f2p, ci, human…). Ungrounded self-declarations are rejected from reinforcement. Accumulated pairs grow the pool and widen the regime.

report_outcome(call_id="1b60f8b814b1", passed=true,
               reporter="your-agent-id", grounded_by="pytest-f2p")

Geometry, not generation

GHOST does not generate patches and does not rewrite them. It is a measurement instrument over representation space: every pool row keeps its provenance (task, authoring model, campaign) because a mixed pool is measured before it is built.

The flywheel

Nightly collection matches outcomes to scans by call_id, deduplicates against the pool, stratifies by authoring agent, and flags distribution poison — then promotion is an owner-supervised, disclosed act. Never silent.

everything else — abstain
What this means: GHOST is not a general-purpose predictor and never claims to be one. The calibration (τ pinned in a governance artifact, LOAO-cross-validated) is served alongside the pool — clients can audit the regime before trusting a single verdict. A verdict without a measured regime is indistinguishable from a guess; GHOST refuses to guess.
Install

One URL, like any other MCP server

Remote HTTP transport (recommended — weights and pool stay on the serving host):

# Claude Code
claude mcp add --transport http ghost http://ghost-mcp:8093/mcp

# opencode / Cursor / any mcpServers client
{
  "mcpServers": {
    "ghost": { "url": "http://ghost-mcp:8093/mcp" }
  }
}

Local stdio (colocated, torch + transformers, no network):

# pool + calibration expected under data/ (env-overridable)
{
  "mcpServers": {
    "ghost": {
      "command": ".venv/bin/python",
      "args": ["server/ghost_server.py"]
    }
  }
}
Auth: when GHOST_TOKEN is set on the server, clients must send Authorization: Bearer <token> — the server refuses to boot unprotected if the token cannot be enforced. Without it, serving is internal-network only.
